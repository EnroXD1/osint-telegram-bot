# Открытый след — Telegram OSINT-бот

Первая версия на Python 3.12 и aiogram 3. Русский интерфейс, автоматическое распознавание запросов, кнопки меню, ссылки на источники и обработка ошибок API. Работает через long polling: публичный сервер и входящие порты для локального запуска не нужны.

Это самостоятельная реализация по приведённым примерам. Доступа к базам @crmchatcontactbot у проекта нет. Бот не выполняет поиск чувствительных данных о частных лицах, не подключает утечки и не идентифицирует человека по лицу.

## Что реализовано

| Запрос | Что бот действительно делает | Источник |
|---|---|---|
| `example.com`, `/domain example.com` | DNS A/AAAA/MX/NS; регистрационные события и статус домена | Google DNS; RDAP по реестру IANA |
| `1.1.1.1`, публичный IPv6, `/ip 1.1.1.1` | Название сети, диапазон, страна регистрации сети, PTR | RDAP; Google DNS |
| `/vin 1HGCM82633A004352` или VIN без команды | Марка, модель, модельный год, кузов, двигатель и другие доступные характеристики | NHTSA vPIC |
| `/phone +79999688666` или обычный номер | Международный формат, допустимость по плану нумерации, справочные сведения о диапазоне | Локальный phonenumbers |
| `name@example.com`, `/email name@example.com` | Синтаксис email и почтовые MX-записи домена | Google DNS; передаётся только домен |
| `github.com/octocat` | Наличие открытого GitHub-профиля, его имя/описание, число публичных репозиториев, дата создания | GitHub API |
| `@octocat`, `/user octocat` | Проверка GitHub и публичного Telegram-канала/группы; ссылки для ручной проверки на других платформах | GitHub API; Telegram Bot API |
| `t.me/username` | Публичная ссылка; сведения о канале/группе, если они доступны Bot API | Telegram Bot API |
| Ссылки VK, TikTok, Instagram, OK | Распознавание платформы и нормализация ссылки; существование и содержимое профиля не проверяются | API этих платформ не подключены |
| `/inn 7707083893`, `/ogrn 1027700132195` | Контрольная цифра и ссылка на ЕГРЮЛ; с ключом DaData — название и реквизиты юрлица | Локальная проверка; опционально DaData |
| ИНН физлица из 12 цифр, ОГРНИП из 15 | Только локальная проверка контрольных цифр | Локальная проверка |
| Госномер, `tg123456`, кадастровый номер | Распознавание формата и объяснение ограничений | Автоматический поиск не подключён |
| ФИО/дата рождения, `/passport`, `/snils`, `/vu`, `/tag`, `/adr`, фото | Объяснение доступных функций; поиск людей и обработка фото не запускаются | — |

Произвольный Telegram-пользователь по ID через Bot API не находится. Совпадение логинов на разных платформах не подтверждает, что это один человек. Для VIN вне покрытия NHTSA результат может быть частичным. Страна регистрации IP-сети не означает местонахождение пользователя. Телефонный справочник не подтверждает активность номера, владельца или текущего оператора после переноса номера. MX не подтверждает существование почтового ящика. Контрольные цифры ИНН/ОГРН не подтверждают регистрацию организации.

## Запуск на Windows

1. Распакуйте архив. Откройте PowerShell в каталоге проекта.
2. Выполните:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1
   ```

   Скрипт создаст `.venv`, установит зависимости и скопирует `.env.example` в `.env`, если файла ещё нет. Он использует установленный Python, либо доступный Python из среды Codex. Рекомендуется Python 3.12. Политика выполнения изменяется только для этого процесса.

3. В Telegram откройте [@BotFather](https://t.me/BotFather), создайте собственного бота командой `/newbot` и получите токен.
4. Откройте `.env` в редакторе и заполните `BOT_TOKEN`. Не отправляйте токен в чат и не публикуйте его в репозитории.
5. Запустите:

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1
   ```

6. Откройте созданного бота в Telegram и отправьте `/start`. Для остановки нажмите Ctrl+C в терминале.

Бот работает, пока запущен процесс и компьютер подключён к интернету. Для круглосуточной работы нужен постоянно включённый компьютер или сервер. Один токен должен обслуживаться одним процессом polling. Бот с уже установленным webhook не запускается: используйте отдельного бота, чтобы не нарушить существующее подключение.

### Доступ и настройки

```dotenv
BOT_TOKEN=значение_от_BotFather
ALLOWED_USER_IDS=123456789,987654321
DADATA_API_TOKEN=
GITHUB_API_TOKEN=
DEFAULT_PHONE_REGION=RU
REQUESTS_PER_MINUTE=10
HTTP_TIMEOUT_SECONDS=10
```

`ALLOWED_USER_IDS` — необязательный список Telegram ID пользователей. Пустой список разрешает доступ всем, кто пишет боту в личные сообщения. Чтобы сначала узнать свой ID, оставьте список пустым, запустите бот, отправьте `/id`, затем добавьте ID в `.env` и перезапустите. В группах бот не обрабатывает сообщения. Укажите ключ DaData только если хотите получать карточки юрлиц; без него остальные функции работают. Доступность и стоимость DaData зависят от вашего аккаунта и квоты.

Неоднозначные числовые запросы вводите явно через `/phone`, `/inn` или `/ogrn`. Номер без `+` разбирается с учётом `DEFAULT_PHONE_REGION`; для международных номеров используйте `+`. Значения переменных среды имеют приоритет над `.env`.

GitHub можно использовать без токена, но общая квота для IP ограничена. Если API сообщает об исчерпанной квоте, укажите свой `GITHUB_API_TOKEN` для чтения открытых профилей. Токен не должен давать права на изменение данных. Он отправляется только GitHub API.

## Linux / сервер

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
cp .env.example .env
# Заполните .env в локальном редакторе.
.venv/bin/python -m osint_bot
```

Есть Dockerfile для самостоятельного размещения. Docker-сборка в этой среде не проверялась.

```bash
docker build -t open-trace-bot .
docker run --env-file .env --restart unless-stopped --name open-trace-bot -d open-trace-bot
```

## Проверка без токена Telegram

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m osint_bot --demo example.com
.\.venv\Scripts\python.exe -m osint_bot --demo '/phone +79999688666'
```

`--demo` выводит карточки в HTML-формате для диагностики. Сетевые запросы требуют доступа к API. Проверки в `tests` используют подставные ответы и не требуют сети или токена.

## Данные и ограничения

Приложение не пишет историю запросов и результаты в файлы или базы. В памяти держатся ID и временные счётчики для ограничения частоты запросов; кэшируется только технический реестр IANA. Фото не скачиваются. Запросы и ответы остаются в Telegram; внешние API и хостинг могут вести свои журналы. Бот не обещает удаление данных у сторонних сервисов.

Обращения выполняются к заданным API. RDAP-сервер выбирается из HTTPS-сервисов официального реестра IANA; перенаправления проверяются по его списку. Бот не посещает произвольные сайты из пользовательских ссылок и не сканирует IP. Локальные и специальные IP/домены отклоняются. Текст источников экранируется перед отправкой в Telegram; ошибки соединения выводятся без ключей и содержимого запросов.

Охват ограничен перечисленными источниками. Здесь нет обещания «найти всё». Для новых функций нужны конкретные доступные API, правила их использования и отдельная реализация. Пример готовой точки расширения: `SourceClient` в `osint_bot/sources.py`, обработчики результатов — в `osint_bot/service.py`.
